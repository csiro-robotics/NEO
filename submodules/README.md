# Vendored Dependencies

This directory contains physical source copies required by NEO. These are not
Git submodules and do not contain nested `.git` directories or symbolic links.
The Conda environment installs them as local editable packages.

| Directory | Upstream | Base revision | Version |
| --- | --- | --- | --- |
| `nerfstudio` | `MikolajZielinski/nerfstudio` | `d8b04cfaa30422de1189ee987ba7d3950b55a650` | 1.1.5 |
| `lerf_bbox` | `csiro-robotics/lerf_bbox` | `112ad9ede65c595e6c0f1f9a675f15891665c4c4` | 0.1.1 |
| `neo_lerftogo` | `csiro-robotics/neo_lerftogo` | `646a023571ec9d8c954dfc632d65600ad5fb3c2b` | 0.1.0 |

The copied Nerfstudio, LERF, and Robot-LERF trees include the uncommitted
source modifications present in the paper-development checkouts when they were
vendored. This is intentional: those changes were part of the working NEO
runtime but were not represented by the base commit hashes alone.

Nerfstudio, LERF, and NeRFiller license files are preserved in their respective
directories. The source `neo_lerftogo` checkout did not contain a top-level
license; its redistribution terms must be resolved before public release. Its
vendored GraspNet components retain their own license files.

Generated bytecode, egg-info, nested Git metadata, local `.env` files,
documentation sites, tests, outputs, and sample point clouds were not copied.
The GraspNet checkpoint referenced by `lerftogo-neo` was retained as a runtime
asset. Robot-LERF's existing PointNet2 and KNN extensions were unpacked from its
upstream Python 3.10/Linux build artifacts and exposed as packages; they
therefore require the documented Python 3.10, Linux, NVIDIA, and CUDA runtime.
